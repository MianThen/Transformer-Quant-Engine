# 本地小模型分卡作业规范

> 来源：quant-backtester-cpp 的 MC-GATE-VALIDATION 项目，32 个卡片文件（C06R 为 C06 的重发，实为 31 项工作）、
> 28 个 goal 轮、约 6000 行 C++。
> 硬数据：**卡作者缺陷 29 次，模型真实缺陷 1 次**。
> 结论先记牢：**瓶颈在卡作者，不在模型**。这个模型是可靠的"字面翻译器"。

## 0. 何时用这个技能

- 有一个明确规格（合同/论文公式/算法描述），要让本地模型写成代码
- 代码量超过单次生成的舒适区（该模型 >300 行就明显退化）
- 需要**机器判分**而不是"看着像对"
- 网络不可用或成本敏感，只能跑本地模型

不适用：探索性设计、需求模糊、需要架构判断的活——那些该自己做或换强模型。

## 1. 一张卡的最小结构

```json
{
  "id": "C07",
  "target": "/tmp/qgate/C07/mc_gate_xxx.h",
  "lang": "cpp",
  "max_rounds": 3,
  "max_tokens": 8192,
  "cwd": "/tmp/qgate/C07",
  "prompt": "……把规格写到模型无法发挥的程度……",
  "build_cmd": "g++ -std=c++20 -O2 -Wall -Wextra -Werror -I<inc> -I. t.cpp -o o.out",
  "verify_cmd": "timeout 30 ./o.out > out.txt 2>&1; rc=$?; if [ $rc -eq 124 ]; then echo C07_FAIL hang; exit 1; fi; awk -f c07_verify.awk out.txt"
}
```

四条硬规矩：

1. **`verify_cmd` 必须带 `timeout N`**，否则模型的死循环会吃掉 worker 的 600 s，
   回灌给它的只有一句无信息量的 `TIMEOUT`。
2. **`build_cmd` 带 `-Werror`**（若目标工程 CI 也是）：warning 在 CI 里就是 error，
   早失败比晚失败便宜。
3. **一条卡只产出一个文件**（header 或 app）。多文件卡会显著提高失败率。
4. **`max_rounds=3`** 足够：该模型第 3 轮还不过，说明是卡的问题，继续喂只会重复同样的错误。

## 2. 卡的六要素（缺一条就多一轮）

### 2.1 完整调用名 + 头文件白名单（最高频的坑）

模型会**从文件名推断命名空间**。写了 `mc_gate_sha256.h`，它就会调
`mc_gate_sha256::sha256_hex(...)`——而实际函数在 `mc_gate` 里，裸名调用。

- 卡里写：**完整签名 + 所在命名空间 + "不要加前缀"**
- include 白名单必须覆盖**所有被调用函数**。漏一个 `sha256.h`，
  模型不会报错，而是**自己实现一个 SHA-256**（前 8 个值全对，块哈希不对）。

### 2.2 可复制的代码，不是伪代码

反面教材：`打印：FILES <manifest 1> <metrics 1> <jsonl 1> <replay 1>`
→ 模型**照着字面打印了尖括号**。

正面：

```cpp
auto exists = [](const char* p){ FILE* f=std::fopen(p,"rb"); if(f){std::fclose(f);return 1;} return 0; };
std::printf("FILES %d %d %d %d\n",
  exists("/tmp/x/manifest.json"), exists("/tmp/x/metrics.json"),
  exists("/tmp/x/decisions.jsonl.gz"), exists("/tmp/x/replay/dataset_0.bin"));
```

**规律：凡是"算出来的值"，就给算它的代码；凡是"格式"，就给 snprintf 模板。**

### 2.3 多类型时逐一列字段与转换

同一张卡里出现两个结构体时，必须写清各自字段与转换：

```
struct Decision   { bool selected; size_t index; bool abstain; const char* reason; };
struct RuleResult { bool selected; int index; double sr; int window; double pbo; };
// 不要把它们塞进同一个数组：index 一个是 size_t 一个是 int，会 -Werror=narrowing
```

### 2.4 外部依赖要自包含

编译期表（`.inc`）里若含 `Family::T5` 这类枚举名，就只能放在 `using namespace` 之后——
模型**总是**把它放在文件头。

修法不是在卡里强调顺序，而是让 `.inc` **自带 struct 定义与 include guard**：

```c
#ifndef XXX_INC
#define XXX_INC
struct GridCell { int cell_id; int family; ... };   // 纯整数编码，不含枚举字面量
static const GridCell kGridCells[] = { {0, 1, 0, ...}, ... };
#endif
```

**原则：凡是"调用方必须按某顺序声明/包含"的设计，都把依赖内置到被包含文件里。**

### 2.5 输出纪律：逐行、可数、带结束标记

```
共 N 行（A 1 行 + B M 行 + …）+ 1 行 XXX_DONE
```

结束标记是验收器的锚点，也防"程序跑一半崩了但前几行对"。

### 2.6 期望输出逐行给出，且必须是**独立算出来的**

- 能从公式推的：用 Python/独立实现算一遍，把结果钉进卡里
- 跨平台会差 1 ulp 的（libm）：钉在**目标机**上跑出来的值，并在验收器里注明"仅同机"
- 统计量：给区间而不是点值（见 4.4）

## 3. 卡前检查表（每次发卡前过一遍）

1. include 白名单是否覆盖**所有被调用函数**？
2. 是否给了**可直接复制**的代码（而不是伪代码/形如输出的占位串）？
3. 涉及多个结构体时，是否逐一列出**字段与转换**？
4. 有编译期表/外部 `.inc` 时，是否让其**自包含**？
5. 目标机的 include 目录是否已同步**所有依赖头**？（漏过 `mc_gate_onc.h`，两轮白跑）
6. `verify_cmd` 是否带 `timeout`？
7. verifier 的断言是否**只断言真正成立的性质**？（见 4.5 的反面教材）

## 4. 验收器（verifier）编写规范

验收器比卡更容易坑自己——**它有 bug 时通常表现为"永远 FAIL"，让你误以为是模型错**。

### 4.1 先做 L0：用"已知正确样本"跑验收器

```bash
awk -f cNN_verify.awk expected.txt   # 必须输出 C NN_PASS
```

**没做 L0 的验收器 = 没有验收器。** 我曾在正样本都挂的情况下跑完 9 条负向对照，
全部"抓到"——其实是假阳性，验收器本身坏了。

### 4.2 负向对照 ≥ 8 条，覆盖这几类

| 类别 | 例 |
|---|---|
| 值错 | 某个数字改 1 ulp / 改小数点 |
| 少字段 | 删掉一行里的一个 `k=v` |
| **顺序错** | 交换两个字段（要求用**位置化**取值才抓得到） |
| 多余行 | 末尾加一行 `FOO 1` |
| 缺结束标记 | 删掉 `XXX_DONE` |
| 键名错 | `above=` 写成 `over=` |
| 结构性 | 两个不同流的指纹相同、`ds` 没进串 |

### 4.3 位置化取值，别用整行正则

用 `match($0, /drift=([-0-9.]+)/)` 就抓不到字段顺序错。用 `$5` 这类位置取值，
再显式检查 `index($3,"analytic=")==1`。

### 4.4 统计类断言要给区间，且按样本量算分辨率

- 1500 reps 时 FPR 的分辨率约 0.07%——别拿 `|Δ|<0.05` 去卡 5% 的量
- 比较"等 FPR 下的功率"时，α* 只能从网格里选，选出的一定不会恰好相等；
  要么给区间，要么接受 `|fpr1-fpr2|` 的残差

### 4.5 反面教材：断言了不成立的"性质"

我断言"门槛回收时 `hi_nosel ≤ lo_sel`（两个边界不重叠）"——**错**。
门槛逐 rep 随实测 `m` 变化，重叠才是正常的。结果 3 轮 VERIFY_FAIL 全是我的锅。

**写断言前先问：这个性质真的必然成立吗？还是只是我期望它成立？**

### 4.6 兜底规则

加一条通配：任何不认识的键/多余的行都判 FAIL。

```awk
/^COST /{ if($2!="total" && $2!="over" && $2!="unknown"){bad++} }
$0 !~ /^(COST|...)/ && $0 != "DONE" { bad++ }
```

### 4.7 测试脚手架的两个坑

- **假驱动会覆盖变异**：用假 `drv.out` 做负向时，若它每次都重新生成产物，
  你的变异会被静默覆盖 → 全部"漏判"。改成从 `stage/` 目录 `cp`。
- **restore 要用相对路径**：`{"dataset_0.bin": ...}` 会把 `replay/dataset_0.bin`
  写回根目录，后续用例全部因"缺文件"失败（假阳性）。

## 5. 模型能力边界（实测）

| 维度 | 表现 |
|---|---|
| 按精确规格填实现 | **强**。给常量、公式、调用名，一次就对 |
| 60–120 行的自包含头文件/脚本 | **稳**。C16/C18–C23/C25/C29 等多为一轮过 |
| 300 行以上的集成/驱动 | **会跌**。C26 换到第 4 版卡才一轮过；C27/C28/C30 各 2 轮 |
| 循环不变量（如 padding 状态机） | **弱**。唯一一次真实缺陷：`if(buf_len>=56){reset;}` 放进 `while` → 死循环 |
| 命名空间/类型推断 | **不可靠**。看文件名猜命名空间、把 A 类型赋给 B 类型 |
| 占位符识别 | **零**。`<foo 1>` 会被原样打印 |

### 什么时候该拆卡

- 目标文件 >200 行 → 拆
- 需要跨 3 个以上已有头文件 → 先做一层薄封装卡，再让上层用它
- 涉及两种结果类型/两条代码路径 → 拆

### 什么时候该直接给代码

以下情况别指望模型"理解意图"，直接把可复制的代码片段放进卡里：

- 死循环/状态机/边界条件
- JSON 拼接的键序与格式
- 文件存在性检查
- 任何"算出来的汇总行"

## 6. 作业流程

```
写卡 → 本地 L0 自检验收器 → 上传到目标机 → 启 worker
     → 看 status（PASS/BUILD_FAIL/VERIFY_FAIL）
     → FAIL 时：先自己手编一次（判断是卡还是模型）→ 改卡生成器（不是改 JSON！）
     → PASS 后：独立复核（换命令重编 + diff + 跑验收）→ 入树 → 提交
```

### 6.1 卡片真源必须是生成器

改卡一定改 `mk_cNN_card.py`，**不要直接改 `card_cNN.json`**——
下次重新生成会把你的修复覆盖掉（我因此白跑 2 轮）。

### 6.2 重跑前必须确认没有残留 worker

两次 relaunch 重叠 → 两个 worker 抢写同一个 `.cpp` → 构建读到写一半的文件，
日志和手工复现**互相矛盾**。`pkill` 后要等 1–2 s 再启动。

### 6.3 FAIL 时先分辨责任

| 现象 | 判断 | 动作 |
|---|---|---|
| 日志说 BUILD_FAIL，但我手编通过 | 大概是环境/残留进程/头文件没同步 | 查 include 目录与进程 |
| 多轮输出**字节完全相同** | 模型卡在同一错误，回灌没起作用 | 改卡，别加轮次 |
| 部分值对、个别值错 | 通常是"某个环节的实现细节没给" | 定位到具体环节，给代码 |
| 全部对、只有一行格式错 | 占位符/格式歧义 | 给 snprintf 模板 |

### 6.4 模型侧缺陷的判别

唯一一次真实缺陷（SHA-256 padding 死循环）的定位过程值得记：
逐层比对 → 均匀流对上 → 正态变换对上 → 最后发现是**常量**（`kSigmaP` 手写字面量
与 `0.10/scale` 差 9.7e-6）。

**教训：不要假设"看起来一样的算法"就是一样的。把中间量打出来逐层比对。**

## 7. 与主体工程集成

- 每张卡的产物入树时，加一个 `test_mc_gate_<name>.cpp`（一行 `#define X_SELFTEST 1` + include）
  注册进 CMake，让 `ctest` 覆盖
- 全部 header-only 模块要加 **include guard**（判据：前 10 行内是否已有 `#ifndef`/`#pragma once`；
  按第 0 行判断会给带注释的头上套双层同名 guard，反而把内容跳空）
- 归档三件套到 `configs/<domain>/cards/`：`card_CN.json`、`verify/cNN_verify.awk`、`expected/cNN_expected.txt`
- 写一个 `tools/run_<domain>_acceptance.sh` 把"L0 自检 + 构建 + 单测 + 驱动探针"串成一条命令，
  `PASS n/n` 是唯一可信的完成信号

## 8. 一句话总结

> 把模型当**编译器**用，不当**工程师**用。
> 它需要的是**规格**，不是**意图**；是**代码**，不是**描述**。
> 每次它出错，先检查自己的卡——29:1 这个比例就是答案。
